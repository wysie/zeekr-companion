## Recording failure

The error is `No camera to record: active=[front], enabled=[back]`. Internal key
`front` means Surround; `back` means Front cabin. The current profile has Surround
and Rear cabin disabled, Front cabin enabled. Manual USER and driver DRIVE attempts
fail immediately before recorder/file creation. Earlier storage-write errors in the
retained report predate these attempts and do not establish this failure's cause.

The app's pipeline builder incorrectly treated any single enabled camera as
Surround. Its cache identity also failed to distinguish Surround-only from
cabin-only. The main-screen layout used the same count assumption. Single cabin
selection therefore continued opening Camera 3 while recording requested a cabin
channel that did not exist. This also invalidated the earlier single-cabin probe
instructions: these exports contain no saved Camera 0/1/2 image.

The fix uses individual channel flags shared by the layout and pipeline builder.
Cabin layouts provide three possible texture slots; only selected roles get
listeners and count toward readiness (also fixes Surround + Rear cabin). Unapplied channel edits require an exit
and reopen, with an explicit instruction at recording start and after storage waits.

To restore the normal surround setup in 2.11.25: enable Surround, disable both cabin
channels, restore Camera mapping to All Auto, fully exit and reopen. The report also
has driver-start and driver-stop ON; disable driver-start again if manual-only
recording is intended. Native recording after restoration still requires confirmation.

`IVehicle.SETTING_FUNC_AVM_SHOW_STATUS` (0x2031FE00) and
`IVehicle.SETTING_FUNC_CEM_SMALL_POP_RES` (0x2031B200). This is stronger evidence of
an AVM control/status interface than the previous export, but no stream URL,

are 0; repeated deliveries do not prove successful video access. Next inspect the
